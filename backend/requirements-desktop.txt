# Desktop packaging dependencies — PyInstaller and its runtime deps.

# Split out rather than appended to the CI step because `requirements.txt` is
# hash-pinned: the hashes put pip into `--require-hashes` mode, and in that mode
# *every* requirement on the invocation must be pinned with a hash. The old
# `pip install -r backend/requirements.txt pyinstaller` therefore failed outright
# once the hashes landed —
#
#     ERROR: In --require-hashes mode, all requirements must have their versions
#     pinned with ==. These do not: pyinstaller
#
# Installing pyinstaller in a second, unhashed `pip install` would have worked
# and would also have put an unverified package into the build that produces the
# shipped desktop binary, which is the exact hole the hash pinning closed.
#
# Not checked by tests/test_pinned_environment.py: these are CI-only build tools
# and are deliberately absent from the application venv, so asserting they are
# installed would fail every local run.
#
# hash-pinned with `pip-compile --generate-hashes` (hashes are not hand-written).
# Regenerate with:
#   pip-compile --generate-hashes --no-header --strip-extras --allow-unsafe \
#     -c requirements.txt -o requirements-desktop.txt requirements-desktop.in
# where requirements-desktop.in contains just `pyinstaller`. The `-c` constraint
# keeps any dependency shared with requirements.txt on the same version.
